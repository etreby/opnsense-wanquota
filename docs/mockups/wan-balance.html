A weight is not a share. MOBINIL's weight of 6 is not a 37% slice — it is not consulted at all, because pf builds its pool from the highest non-empty tier and MOBINIL is below it. The weight is still kept current on purpose: it is the ratio that applies the instant the concentration is released, which is what makes the handover clean. Reading the weight as a share is the mistake this column exists to prevent.

Why this is safe to leave on
  1. Never force_down. Drain decides which link is preferred; taking one out of service stays the guardrails' decision. A demoted gateway is live standby and takes over in seconds — measured, not assumed. A layout that would leave the first tier empty is refused.
  2. A floor guard with no rate in it. A provider at or past 90% of its quota is never concentrated onto, however much allowance it appears to have. The engage test proves the allowance cannot run out, but that proof rests on a lagging average of demand — this one rests on nothing.
  3. Overuse takes precedence. While the guardrail is acting on any provider, drain stands down entirely rather than fighting it over the same tiers.
  4. Only when it moves. Weights and tier names are both compared before anything is written, so a run computing the same answer saves no configuration and reloads no filter.
  5. Releasing undoes, it does not merely stop asking. The recorded original layout is restored, and turning the mode off releases too. Revert weights and uninstalling both put everything back.

The arithmetic

One line, and both terms already come from the quota cards.

urgency = max(0, remaining − reserve) / max(1, days_left)
weight  = max(1, round(urgency / peak × top_weight))

The emergency reserve is subtracted first, so the balancer never spends the buffer the guardrails depend on. When every provider scores zero, all weights return to 1 and the group is back to equal sharing.
