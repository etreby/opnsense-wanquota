MOBINIL holds nearly twice the remaining allowance, and is still the lower priority: it has three times as long to spend it. ETISALAT must move 17.77 GB a day to use up its 129.4 GB before the cycle turns in 7 days, against MOBINIL's 10.88 — so ETISALAT takes the larger share and the gigabytes that would have expired get spent.

Why this is safe to leave on
  1. Weights only. A tier move is failover, which idles a link — the waste this exists to end. Revert weights puts every original back, and so does uninstalling.
  2. A floor of 1. The balancer shifts the ratio and never starves a link. Weight 0 would be it taking a link out of service, which is not its decision.
  3. Overuse takes precedence. A provider the guardrail has failed over or cut off is excluded and held at weight 1. Its row says so instead of showing a weight that will not be written.
  4. Only when the ratio moves. Integer weights are compared before anything is written, so a run computing the same answer saves no configuration and reloads no filter.

The arithmetic

One line, and both terms already come from the quota cards.

urgency = max(0, remaining − reserve) / max(1, days_left)
weight  = max(1, round(urgency / peak × top_weight))

The emergency reserve is subtracted first, so the balancer never spends the buffer the guardrails depend on. When every provider scores zero, all weights return to 1 and the group is back to equal sharing.
